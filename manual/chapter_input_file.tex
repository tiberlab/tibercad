




\chapter{Input for TiberCAD }

Input for  \TiberCAD is  composed by an  input  file e.g. "input.tib" and a mesh file generated by a mesher software: as for  now, mesh files from GMSH (*.msh,  v.1 and v.2.0 )  and from ISE-TCAD (*.grd) are  supported.

Be sure that the material files are   in the  correct directory  (as specified in \ref{matfiles}).

To run the program, type:
\textbf{tibercad}  \textit{input\_file\_name}

\section {Description of Input  file structure }

A valid  input file for \TiberCAD is a  text file with the    structure  described in the following.


  In the whole input file, everything  following a '\textbf{\#}' is considered as a comment and is disregarded;
 blank lines can be present anywhere and are disregarded too.

Input file is composed by several \textbf{sections}:
%
each \textbf{section} begins with a \textbf{section-name} preceded by \textbf{\char`\"{}\$\char`\"{}} (e.g. \$Physics ).

A section is enclosed between  \textbf{\char`\"{}\{\char`\"{}} and \textbf{\char`\"{}\}\char`\"{}} brackets and is possibly composed  (depending on the  section)
  by a variable number   of  \textbf{blocks}  enclosed between  \char`\"{}\{\char`\"{} and \char`\"{}\}\char`\"{} brackets.

   Each  \textbf{block} can be possibly composed by one or more blocks, each preceded by a block-name. 
 

The  elementary block ( \textbf{parameters-block} ) is a block which  contain 
%Except the model-blocks and the BC\_\-regions-blocks (see in the following), each block can contain 
zero or any number of   \textbf{parameter assignements} in the  form:

 \char`\"{}\textit{tagname} = \textit{tagvalue}\char`\"{}, 

where

\begin{itemize}
 \item \char`\"{}\textit{tagname}\char`\"{} is a string
\item \char`\"{}\textit{tagvalue}\char`\"{} is a single numerical or string item or a list of items between \char`\"{}(\char`\"{} and \char`\"{})\char`\"{} parenthesis and separated by commas.
e.g. \textit{(cathode, anode)} 
\end{itemize}

%  \char`\"{}\textit{tagname}\char`\"{} is a string and \char`\"{}\textit{tagvalue}\char`\"{} is a single numerical or string item or a list of items between \char`\"{}(\char`\"{} and \char`\"{})\char`\"{} parenthesis and separated by commas. 
Format is free for the parameter   assignements, provided that they are separated by spaces. Everything which follows a '\textbf{\#}' is considered as a comment and is disregarded.

For example:
\begin{verbatim}
driftdiffusion
  {
    coupling = poisson
    nonlin_max_it = 70
    nonlin_rel_tol = 1e-10
   
    ls_max_step = 2
    #ls_type = none
    discretization = fem
    integration_order = 2
    #pc_type = composite
    ksp_type = bcgs
    #quasi_equilibrium = (cathode, anode)    
  }
\end{verbatim}
 Here and in the whole input file a string item can include a combination of characters, special characters and numbers, but not spaces; if a space is found , the string item is taken as terminated.

 \textbf{Geometry}, \textbf{Device}  ,  \textbf{Scale},  \textbf{Models}  ,  \textbf{Physics},  \textbf{Solver},   \textbf{Simulation}

\textit{material} (mandatory) :  name  of the  material associated to the  present region; it  can be  an  alloy,  in this  case the  keyword \textit{x } must be  present.

\textit{x} : alloy concentration; e.g. in $Al_xGa_{1-x}As$,  x is  Al concentration

If it is not  present, the  \textbf{TiberCAD} \textbf{Region} name must be a valid name of an ISE-TCAD  mesh region.

\textit{structure} : crystal structure ( wz = wurtzite,  zb =  zincblend)

\textit{x-growth-direction}, \textit{y-growth-direction}, \textit{z-growth-direction}: Bravais  vectors with Miller  indexes for  wurtzite crystal (4 element vectors) or zincblende crystal  (3 element vectors).

\textit{doping} : doping  concentration [cm$^{-3}$]

\textit{doping\_type} : donor or  acceptor

\textit{doping\_level}: energy level of  the dopant [eV]

\section{Scale  section }

The section \char`\"{}\textbf{Scale}\char`\"{}  is  dedicated to the  optional  definition of  Non-Continuous Media regions for the  device: these
 regions wiil  be  described and  studied at  a different  scale (e.g. atomistic, circuit level lumped model, etc.)
As for  now,  just the  atomistic  description is  implemented.
\textbf{Atomistic} blocks, if present,  specify a possible atomistic description associated to one or to a group 
of  physical regions described by \textbf{Region} blocks. So, for each \textbf{Atomistic} block defined in Input file,
an atomic structure description will be  generated and used to solve a simulation problem with an  atomistic approach.
The association to the  physical (macroscopic) regions of the  device allows the implementation of  multi-scale calculations. 

Each  \textbf{Atomistic} block must be preceded by the keyword \char`\"{}\textbf{Atomistic}\char`\"{}, followed by the  (single-word) name of
 the atomistic region.

\begin{verbatim}
Atomistic  TB_1
 {
    physical_regions = ( barrier_1, qwell, barrier_2) 
			            # physical  regions to be described 
                                    # with atomistic model.
 }
\end{verbatim}

Here are the  description of  the available keywords for an \textbf{Atomistic} block.

\textit{physical\_regions} (mandatory): list of the physical regions ( \textbf{TiberCAD} \textbf{Regions} or \textbf{Clusters} )  of 
the device associated to an atomistic description. \textit{all}  (default)  is used to specify all the physical regions.

\textit{path} (optional): path for importing an atomistic structure from an external file. \textit{xyz} and \textit{gen} formats are supported, 
and are automatically recognized by file extension. Each of the atom positions is imported as is, so the atom  coordinates must be consistent with the  geometry of the device.

If no path is specified, the \textbf{TiberCAD Atomistic Generator}  builds the atomistic structure; it is  constructed as a bulk crystal
structure, covering with proper atomic species the physical regions and taking in account the dimension  of the problem (up to now 1D
structures are supported)............ 

Atomistic Generator options, to be put in the Atomistic section, are  described in the  following.

\textit{reference\_region} (mandatory): the Atomistic Generator can only build pseudomorphical heterostructures. A reference region must be defined
to specify from which region ( \textbf{TiberCAD} \textbf{Regions})  to get structure parameters such as lattice constants, which  
depend  on the material defined in the reference region.

\textit{passivation} (optional): \textit{no} is default option. If set to \textit{no}, no passivation is performed. If \textit{yes} is specified, a hydrogenation of the structure
is performed, taking into account the structure periodicity. Up to now, hydrogenation is supported fo Silicon structures. .

\textit{preserve} (optional): Default is  \textit{none}.  In some cases it is requested to build a structure in which the atom basis or the conventional cell has be preserved, 
regardless to mesh geometry. 
If \textit{none} is specified, no conservation is performed and only atoms strictly belonging to 
geometrical regions are put in  the atomic structure. If \textit{lattice} is specified, atom basis is preserved (e.g. to preserve anion/cation couples). If 
\textit{conventional} is specified, conventional cell is preserved. ..............

\textit{y\_lenght} (optional): Atomistic Generator builds the minimum periodical structure along \textit{y} and \textit{z} directions.
If y\_lenght is specified, the structure will be at least y\_lenght sized along y\_growth\_direction. Exact lenght is internally defined
in order to keep structure periodicity.

\textit{z\_lenght} (optional): same as above, for the \textit{z} direction.

   In \char`\"{}\textbf{Models}\char`\"{} section, one or more  model-blocks must be present: each model-block must be preceded by the keyword \char`\"{}\textbf{model}\char`\"{}, followed by the (single-word) model name. 
 This must be the   name of  one of the  \TiberCAD  simulation models.
 
Here are the simulation models implemented until now:  \textbf{driftdiffusion}, \textbf{thermal}  ,  \textbf{excitontransport},  \textbf{macrostrain},
\textbf{efaschroedinger}, \textbf{opticskp},  \textbf{opticalspectrum}.
   Each model-block can  contain some  optional blocks, to be written in the  following order:
   
 %  one or more optional Boundary Condition regions blocks (\textbf{BC\_\-regions}-block).
   
   
 %   \char`\"{}\textbf{Models}\char`\"{} section can contain also 
   
\begin{itemize}
	
   \item one    "`options"' block, preceded by the keyword \char`\"{}\textbf{options}\char`\"{}. This block can contain    general  options for the present  model.
	\item  one or more  \textbf{physical\_model} blocks: each physical\_model block must be preceded by the keyword \char`\"{}\textbf{physical\_\-model}\char`\"{}, followed by the (single-word) name of the physical model.
	Each physical\_model block can contain parameters  relevant to a specifical model of a physical property or quantity related to the present model.
\item    one or more  Boundary Condition regions blocks (\textbf{BC\_\-regions}-block).
   The BC\_\-regions-block must be preceded by the keyword \char`\"{}\textbf{BC\_\-Regions}\char`\"{} and it is composed by one or more parameters-blocks, each preceded by the keyword \char`\"{}\textbf{BC\_\-Region}\char`\"{} followed by the (single-word)  name of the boundary condition region. This parameters-block can contain the possible description of the boundary region.
\end{itemize}


 
These optional blocks must be strictly in this order: first the \textbf{options}, then the \textbf{physical\_\-model}, and finally the \textbf{BC\_\-regions}-blocks. A detailed description of the possible parameters for these blocks  follows.



\subsection{options block }

\begin{verbatim}
options
    {
     simulation_name = driftdiffusion
     #physical_regions = all
     physical_regions = (channel_1 , channel_2)
    }
\end{verbatim}

\textit{simulation\_name}: user-defined name of the particular instance of  the simulation model defined for this block. More than one simulation (with different  name and properties) can be  defined,in separated model blocks, which refer to a same  \TiberCAD  simulation model. If simulation\_name is  not assigned,  by default the \TiberCAD model name is taken as current simulation\_name.

\textit{physical\_regions}: (list of) physical region(s) to  which the  present simulation model will be  applied.
Physical region(s) are the  \textbf{TiberCAD regions} or  \textbf{clusters} as  defined in  \textbf{Device}  section 

% can be either integer numbers, consistent with the physical regions set assigned through GMSH, or strings, 
% corresponding to the  region names defined in ISE grid  file, or  even .
Default value  is  "`all"' (all  physical regions of the  device).
In a list, the names must be separated by comma  and  enclosed between '(' and ')' parenthesis 


\subsection{physical\_model block }

\begin{verbatim}
    physical_model recombination
    {
      model = SRH
    }
\end{verbatim}

\textbf{recombination}:

\textit{model}:  SRH,direct, exciton\_generation,  exciton\_dissociation

\textit{exciton\_simulation}: excitons


\textbf{electron\_mobility}

\textit{model}: doping\_dependent

\textbf{hole\_mobility}

\textit{model}: doping\_dependent



\subsection{BC\_region block }

\begin{verbatim}
 BC_Region anode
      {
        BC_reg_numb = 2
        type = ohmic
        #voltage = 0.0
        voltage = @Vb[1.5]
      }
\end{verbatim}



%For each BC\_region:

\textit{BC\_region}: name of the  present boundary  region

\textit{ BC\_reg\_numb}:  BC region ID(s) as  specified in the meshing  program (GMSH).

\textit{ type}: type of  boundary condition: ohmic,  schottky,...  ,  substrate (for strain calculations).

\textit{ voltage}:  value of voltage [V] applied to the present BC region (for ohmic and  schottky BCs); it can be the  value of a sweep  variable 'Vb', indicated with  \symbol{64}Vb. A possible default value can be indicated in parenthesis:  \symbol{64}Vb[1.5]

\textit{ zero\_grad\_fermi\_h}, \textit{ zero\_grad\_fermi\_e}: if true set  Neumann b.c. to the fermi level in the b.c. region.

If \textit{type} is \textsl{substrate} (for \textbf{strain} calculations):

\textit{material} : name of  material in the \textsl{substrate}  region. 

\textit{structure} : crystal structure ( wz = wurtzite,  zb =  zincblend)

\textit{x-growth-direction}, \textit{y-growth-direction}, \textit{z-growth-direction}: Bravais  vectors with Miller  indexes for  wurtzite.

   \item \textbf{sweep} block, preceded by the keyword \char`\"{}\textbf{sweep}\char`\"{}. This block  contains  the  setting for a set of  calculations applied to a boundary region (e.g. to a drain contact for the calculation of a IV characteristic).
   

\begin{verbatim}
sweep
  {
    simulation = driftdiffusion 
    variable = Vb
    start = 0.0
    stop = 4.0
    steps = 80
    plot_data = true
    plotvariable = current
  }
\end{verbatim}

\textbf{variable} : name of  the  variable to which   sweep is  applied: its value is assigned to a quantity (e.g. voltage) in a BC Region section.

\textbf{start} , \textbf{stop}, \textbf{steps}: sweep starts from \textit{start} value, is repeated  \textit{steps} times and stops in \textit{stop}

\textbf{simulation} : name of  the  simulation (model) associated to the  sweep  calculation.

\textbf{plotvariable} : specify  the  integrated quantity to  be  calculated during the sweep and that will be shown in the output  file 
sweep\_\textit{modelname}\_\textit{sweepvariable}.dat,  eg.  sweep\_driftdiffusion\_Vb.dat  for  a  sweep of  current calculation on the  variable \textit{Vb} (typically a contact voltage)  

\textbf{plot\_data} : default is  \textit{false}; if  it is  set  to \textit{true}  output data  will be  written for  each  step of the  sweep calculation, otherwise just  the  results  for  the  final step  will  be  present  in  the  output.


  \item  \textbf{selfconsistent} block , preceded by the keyword \char`\"{}\textbf{selfconsistent }\char`\"{}. In this block it is possible to define a self-consistent calculation based on two different simulation models (e.g. driftdiffusion and excitontransport).
\begin{verbatim}
selfconsistent
  {
    flavour = relaxation
    simulations = (driftdiffusion,  excitons)
  }
\end{verbatim}
In  \textbf{simulations}  the  list of  simulations to  be  performed self-consistently is  specified.
%\textit{flavour}   defines ...

Now  it  is  possible  to  execute the  specified simulations in self  consistent  way,  by  using the \textbf{selfconsistent} keyword 
like  a  simulation name, 
in the 
\textbf{solve}  assignement,  e.g.  \textit{solve = selfconsistent} ,    or  even  in  the  \textbf{sweep} section,  with, for  example,  
 \textit{simulation = selfconsistent}.


\end{itemize}

  }

\section{Simulation section }

In this  section one  can  specify  several general parameters and settings  for  the  actual  calculation to be  run, such as the mesh file to be  used, the dimension of  simulation, the process-flow of  simulation, etc.

\textit{searchpath} :  path for  material  files \label{matfiles}

\textit{meshfile} : name of  mesh file. N.B.: the extension is mandatory! ( \textit{.grd} for ISE-TCAD, \textit{.msh} for GMSH mesh file v.1 and v.2.0 )

\textit{mesh\_units} : units of  measurements used in the  meshing (relative to meters): e.g., $10^{-6}$ for  $\mu m$

\textit{dimension} :  dimension of  simulation (1,2,3)

\textit{temperature} :  temperature  of the system

\textit{solve} : list of  simulations to  be  executed, in the order of  execution; if the list   contains "`sweep"', a sweep is  performed as specified in \textit{sweep} block in the  \textit{Solver} section.   

\begin{verbatim}
  solve =  (strain,driftdiffusion, quantum_electrons, quantum_holes)
\end{verbatim}



\textit{resultpath} :  path for output  directory 

\textit{output\_format} : format of  the  output data: \textit{gmv} for  \textbf{GMV} ,  \textit{ise}  for  \textbf{Tecplot} , \textit{grace} for \textbf{xmgr} (ascii data column type),  \textit{vtk} for  \textbf{Paraview}.

\textit{plot} :  list of output variables which are calculated and available in output  files. See the  corresponding chapters for the  available output variables for each model.

\section{Output description}


At the end of  the  execution, the  program will  write  the  results of  the  simulation  in the  directory specified by \textit{resultpath} , with the  format  specified by \textit{output\_format}.  The  output  variables  are specified in  the  list  \textit{plot}.

TiberCAD  output is  divided in  three  classes: \textbf{nodal}, \textbf{elemental} and  \textbf{integrated}  quantities.

\textbf{Nodal}  quantities are all  the  quantities associated with the nodes of  the  mesh,  such as  Fermi level,  electron and  hole  density,  conduction and  valence band, etc..  The output  values for  these  quantities are reported in  the  files  \textit{modelname}\_nodal.\textit{ext} ,  where  \textit{modelname} is  the simulation model used for the  calculations and  \textit{ext} is  the  extension of  the  chosen  file  format. 

In the  case  a  sweep  calculation is  performed and  the  \textbf{plot\_data} keyword is  set  to  \textit{true}, the output files  are of  the  kind \textit{modelname}\_nodal\_\textit{sweepvariable}\_\textit{step}.\textit{ext}, where  \textit{sweepvariable} is  the  variable with respect to  which the  sweep is  performed (e.g. gate voltage) and  \textit{step} is  the  value of  this  variable  at that step;  e.g  \textit{driftdiffusion\_nodal\_Vb\_0.000.dat} for the  result at the step Vb = 0.0 . 

\textbf{Elemental}  quantities are all  the  quantities associated with the elements of  the  mesh,  such as  current density.
The output  values for  these  quantities are reported in  the  files  \textit{modelname}\_elemental.\textit{ext} .

In the  case  a  sweep  calculation is  performed and  the  \textbf{plot\_data} keyword is  set  to  \textit{true},
 the output files  are of  the  kind \textit{modelname}\_elemental\_\textit{sweepvariable}\_\textit{step}.\textit{ext}.
e.g. \textit{driftdiffusion\_elemental\_Vb\_1.150.dat}

\textbf{Integrated}  quantities are the  quantities which  are  not  associated to the  mesh but  are obtained by an integration on real or reciprocal space,  for  example  current at the  contacts of  a  diode or  quantized energy levels  in  a  quantum  well.
These \textbf{Integrated}  quantities  are displayed in separated files,  with the  format \textit{simulationname}.\textit{ext}
 e.g  \textit{quantum\_electrons.dat},  where \textit{simulationname} is  the  name of the model (simulation) associated to the  results. 

 If  a  sweep  is  performed,  the output  file gets the  format   sweep\_\textit{simulationname\_variablename.ext},
where  \textit{variablename} is the variable  with respect to  which the  sweep is  performed, e.g. \textit{sweep\_driftdiffusion\_Vb.dat}.
Inside the  file,   output values for all  the  steps  of  calculation are shown.

Finally,  a  last class of  output files is  the  \textbf{Materials}  output. These  files  contain the information about   the physical regions of  the  device;  for  each  class  of  simulation, a  different material file is  produced, containing  all and  only the  mesh regions associated to that simulation model. The  file has the  format  \textit{simulationname}\_materials.\textit{ext},   e.g.
\textit{driftdiffusion\_materials.dat }

% \section{Physical and boundary regions in  TiberCAD }
% 
% 
% When TiberCAD  is  run,  it  reads  the  mesh  file which  contains  the finite element  grid  which meshes the  geometrical description of  the  device or  nanostructure,  and  which will be  the  basis of  PDE  discretization.
% 
% 
% To  execute the  proper  simulations, TiberCAD needs  some  information about  the   physical and boundary regions  associated with the  mesh:
% a physical region associates all  the  elements  corresponding to  an  homogeneous  part  of  the  device (usually  related to  the  same  material or  doping).  These regions  are  referred to as \textbf{mesh\_regions}  in  TiberCAD.
% \
% Boundary regions  are  needed to  specify   boundary  conditions (b.c.)  for  the  solution of  the PDEs  of  our  simulation.
% By  default,  to all   the  external boundary  of  the  device  a  Neumann b.c. is  imposed,   meaning  null  derivative  of  electric  field  and  zero  flux  of  current  normal to  the  boundary.  These are  the  usual  b.c.  applied in  the   simulation  of  electronic  devices;  in   particular, these  conditions are  implicitly  satisfied by using  the  finite  element  formulation..
% Usually,  one  needs  to  impose   also   specifical  b.c.  to  the  device,  relative,  most  often, to  contacts of  some  kind (ohmic, schottky),  but  also   heat and  temperature b.c.  or  reference substrates  for  strain  calculations.
% These  regions,  (constituted by  surfaces , lines or  points,  respectively  for  3D  ,  2D  and  1D  simulations) are  referred to  in  TiberCAD with  the  keyword   \textbf{BC\_reg\_numb}.
% 
% 
% It  is  important to  know  that  the  information about  the   physical and boundary regions  must  be  present in  the  mesh  file  before it  is  read  by  TiberCAD,  and  thus  have  to  be  produced by  making  use of  the  modeling/mesher  software.
% As  for  now,  TiberCAD is  compatible  with the  mesh  output  of  the  following   softwares :  GMSH v.2 and  ISE-TCAD  v.9.5.
% 
% By  means  of  the  utility DEVISE    of  ISE-TCAD  v.9.5,  it  is  possible  to  design and  mesh  a  device;  after the  meshing  has  been    successfully completed,  an  output  file is  produced,   with  the  extension  \textit{.grd}.  This  file  contains  all  the  description of  the  mesh and  also  the  list  of  the  user defined  material  regions    and  contact  regions.
% By  reading  this  \textit{.grd} file  in  TiberCAD,  one  can  refer  to  the  ISE TCAD material  regions,  simply  with  the  user-defined name,  which is  present  in  the    \textit{.grd}  file.  This  name  should  be  unique in  the  whole  device.
% In the  same way,  ISE TCAD Boundary regions (\textit{Contacts})  can  be  referred to in   TiberCAD  by  means  of  their  user-defined name, present in  the   \textit{.grd} output  file,  too.
% 
% If  GMSH  program  is  used  to  model and  mesh  the  device,  a  bit  more  care  has  to  be  taken.
% In  the  context of  GMSH,  it  is  possible to  define  several 1,  2  and  3D \textit{Physical Entities}.
% These \textit{Physical Entities} allow  to  associate one or more  geometrical  entities to  a  single  numerical  ID, so  that  several  
% \textbf{mesh\_regions}  and  \textbf{BC\_reg\_numb} can  be  defined and  referred  to  by  TiberCAD.  
% Here is  a  simple example  of   a  script  to  generate a  1D geometrical  model ( \textit{*.geo})  file in  GMSH 
% 
% \begin{verbatim}
% Point(1) = {-25,0,0,0.5};
% Point(2) = {0,0,0,0.002};
% Point(3) = {25,0,0,0.5};
% Line(1) = {1,2};
% Line(2) = {2,3};
% 
% 
% Physical Line(1) = {2};
% Physical Line(2) = {1};
% Physical Point(1) = {3};
% Physical Point(2) = {1};
% \end{verbatim}
% 
% Here,  first the  \textbf{Point}s  and  \textbf{Line}s  geometrical  entities  are  defined.  Then,  two  physical  regions are  defined, each  associated to  one  of  the  two  geometrical  entities:  \textbf{Physical Line(1)}  and \textbf{ Physical Line(2)}.  In this  way,  these  physical  regions are made  available for  TiberCAD,  and  will be  used  to  associate them  to  a  TiberCAD region through the  keyword \textbf{mesh\_regions },  as  follows:
% 
% 
% \begin{verbatim}
% Region reg_1
%    {
%      mesh_regions  = 1
% 
% ............
% 
% Region  reg_2
%    {
%      mesh_regions  = 2
% 
% ...........
% \end{verbatim}
% 
% 
% Then,  in  the  GMSH  script,  two  \textbf{Physical Point }  are  defined, \textbf{1}  and \textbf{ 2},   and  associated to  the  first  and  to  the   last  point  of  our  1D  device.  These  points  are  needed  to  impose  some  boundary  conditions   and  in this  way  they  are made  available for  TiberCAD,  and  will be  used  to  associate each  of  them  to  a  boundary  condition  region, through the  keyword  \textbf{BC\_reg\_numb}
% 
% \begin{verbatim}
% BC_Regions  
%     {
%       BC_Region cathode
%       {
%         BC_reg_numb = 1
% 
% ......................
% 
% 	BC_Region anode
%         {
%           BC_reg_numb = 2
% 
% ....................
% 
% \end{verbatim}
% 
% 
% In  2D  case,  a  set  of  \textbf{Physical Surface}  will  be  defined  to  be  used  as   \textbf{mesh\_regions},  while  
% \textbf{Physical Line}  is  used  for  boundary  conditions.
% 
% Finally,  in  3D  case,  \textbf{Physical Volume} is   used  to  define  \textbf{mesh\_regions},  while \textbf{Physical Surface} is  used  to  define  boundary  conditions.
